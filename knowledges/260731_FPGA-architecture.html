260731 · FPGALUTCLBBRAMDSPASIC

0. 先修正一个认知：ASIC 中寄存器真的"稀缺"吗？

更准确的说法是：ASIC 中每增加一个寄存器，要付出真实的面积和功耗代价；FPGA 中寄存器是预置的——你不用它也在那里。

ASIC — 按需定制

你写 RTL 时用了多少寄存器 → 综合出来就是多少个 DFF → 每个 ~24T → 面积精确按需付费。

优化目标：减少寄存器数量。多打一级流水线 → 面积 ↑、功耗 ↑。所以 ASIC 设计者在不影响时序的前提下会尽量共享寄存器、减少流水级数。

少用寄存器 ≠ 没有寄存器可用。一颗中等规模 SoC 轻松有几百万个 DFF。

"稀缺"是相对 FPGA 而言的——在 ASIC 中你不会随便加流水线，因为每个寄存器都是真金白银。

FPGA — 预置架构

FPGA 芯片出厂时，每个 Logic Element 已经自带一个寄存器。你不用它 → 它闲置浪费。你用它 → 没有额外成本。

优化目标变了：寄存器几乎免费，多打流水线反而降低关键路径延迟。FPGA 设计者习惯疯狂加流水级——反正寄存器就在 LUT 旁边，不额外占地。

"寄存器丰富"不是说 FPGA 寄存器比 ASIC 多——而是说用寄存器的边际成本为零，这是一个经济/架构问题，不是数量问题。

1. FPGA 核心可编程资源全景

🔲
LUT (查找表)
组合逻辑的基本单元。本质是一个小 SRAM，输入端作地址线、输出端读存储值。通常为 4–6 输入 LUT。Xilinx 7系列：6-input LUT（可拆为2个5-input）。
📦
Flip-Flop (寄存器)
每个 LUT 配一个 DFF。LUT 的输出可选经过或不经过寄存器。这就是"FPGA 寄存器多"的来源——每个逻辑单元都预置了一个。
🧱
CLB / Slice
LUT + FF 的集合。Xilinx: 1 CLB = 2 Slices。1 Slice = 4×LUT6 + 8×FF + 进位链 + MUX。这是 FPGA 逻辑阵列的基本建筑块。
🔗
Switch Matrix (互连)
CLB 之间的可编程连线网络。占据 FPGA 芯片面积的 ~60–80% 和功耗的大部分。
💾
BRAM (块 RAM)
专用 SRAM 硬核。18Kb 或 36Kb 每块，可配置为单口/双口/简单双口/FIFO。同步读写。关键存储资源。
✖️
DSP Slice
硬化乘加单元。典型规格：18×25 或 27×18 乘法器 + 48-bit 累加器。做数字信号处理时比 LUT 搭乘法器快 ~10×、省 ~100× 面积。
📡
IOB (IO Block)
可编程 IO 焊盘。支持 LVCMOS、LVDS、SSTL、HSTL 等数十种电平标准。内置 SERDES（串化解串器）用于高速接口。
⏱
时钟管理
PLL / MMCM 锁相环，用于倍频、分频、相位调整、去抖动。全局时钟网络（BUFG）以低偏斜驱动整个芯片。
🔌
硬核 IP
PCIe Gen3/4/5 控制器、DDR4/5 内存控制器、高速收发器 (GTY/GTH, 达 28+ Gbps)、嵌入式处理器 (ARM Cortex-A/R 核)。

3. 关键洞察：为什么 FPGA 中"寄存器近乎免费"

回到最初的问题——这不是简单的资源多少，而是架构哲学的根本差异：

维度ASICFPGA
寄存器来源 综合器按 RTL 实例化 DFF 每个 Slice 预置 8 个 DFF
用寄存器的代价 面积↑ (~24T/bit), 功耗↑ 零边际成本（已经在芯片上了）
不用的代价 零（不存在） 浪费（但你已经为整颗芯片付过钱了）
流水线策略 谨慎加流水——只在需要时 激进加流水——"免费的午餐"
典型设计风格 寄存器共享、FSM 编码优化 高流水、宽数据通路、1-cycle 操作
寄存器资源上限 理论上无硬上限（面积限制） 硬上限（芯片出厂已固定）
💡 代码风格的关键差异

ASIC 思维："这段逻辑能复用吗？我可以少几个寄存器吗？这个状态机能少编码几个 bit 吗？"——每一处节省都转化为更小的面积和更低的功耗。

FPGA 思维："这个操作能拆成多级流水吗？能加一级流水来打断长组合路径吗？"——寄存器反正就在 LUT 旁边，不用白不用。关键路径从 5ns 降到 2ns → 时钟频率从 200MHz 提 500MHz，代价就是多用了几百个你本来就有的 DFF。

同一个人做 ASIC 和 FPGA 设计，代码风格可以完全不同——这不是水平问题，是架构约束问题。

4. BRAM 在 FPGA 中的角色

FPGA 中"BRAM"和之前讨论的"BRAM = FPGA 内的 SRAM 硬核"是一回事。在 FPGA 内部结构视角下：

  • BRAM 是与 Slice 并列的独立列资源，均匀分布在芯片上（通常每列 CLB 旁边嵌几块 BRAM）
  • 典型规格：18Kb/块（Xilinx），可级联为大容量，也可拆分为两个 9Kb 独立使用
  • 配置模式：真双口（两个独立读写端口）、简单双口（一读一写）、单口、ROM、FIFO
  • 数据宽度可配：1、2、4、9、18、36 bit
  • 和分布式 RAM（LUT 搭的 SRAM）的区别：BRAM 容量大、功耗低、但延迟固定（通常 1 周期）；分布式 RAM 延迟低、容量小、可灵活配置
  • 在你的存储系统工作中：BRAM 常用来实现小容量行缓冲、Cache Tag 阵列、FIFO——用 LUT 搭这些功能会烧掉几千个 Slice，而一块 BRAM 就搞定

5. DSP Slice：为什么 FPGA 能做信号处理

如果只用 LUT 搭一个 18×18 乘法器，大约需要 400+ 个 LUT。一片 FPGA 有几十万个 LUT 听起来很多，但几千个乘法器下去就全耗光了。

DSP Slice 把乘法器、累加器、流水线寄存器硬化——一个 DSP48E1 完成 25×18 乘法 + 48-bit 累加，只需 1 个 DSP Slice（而不是 400 个 LUT），还能跑到 500MHz+。

中等规模 FPGA（如 Kintex-7 410T）有 1,540 个 DSP Slices。这对存储控制器中的 ECC 计算、NAND 信号处理、DDR 校准算法是关键的硬件资源。
