锁存器·触发器·寄存器·缓存 — 关系与内部结构

🔑 核心认知

锁存器 → 触发器 → 寄存器是一条包含链：锁存器是原子构件，两个锁存器拼成触发器，N 个触发器并排成寄存器。

缓存是另一条路：用 SRAM 阵列（6T 单元），和寄存器走完全不同的物理实现。缓存 ≠ 一堆触发器。

一、锁存器 (Latch) — 原子构件

D 锁存器内部结构 · ~10–12 个晶体管

内核：1 个传输门（2T）+ 2 个反相器（各 2T）构成正反馈环 + 时钟控制电路（产生 CK/CK̅，~4T）。

工作方式：

  • CK=1 → TG 导通 → D 直通到 Q（透明状态，像一根导线）
  • CK=0 → TG 断开 → 反相器对形成正反馈环，锁住 Q 值（锁存状态）

缺点：CK=1 期间 D 的任何跳变都会传到 Q——在同步数字系统中这是个灾难，因为组合逻辑的毛刺会穿透锁存器。

二、触发器 (Flip-Flop) — 边沿触发的实现

D 触发器内部结构 · Master-Slave · ~20–24 个晶体管

内核：两个 D 锁存器串联，给相反极性的时钟。

为什么解决了锁存器的问题？CK=0 时只有 Master 透明、Slave 锁存——D 的变化"悄悄"传到了中间节点 M，但 Q 不变。CK 上升沿瞬间，Master 锁存（M 冻结），Slave 变透明（M → Q）。从外部看，Q 只在上升沿那一刻更新。CK=1 的剩余时间里，Master 已锁存，D 的任何变化都进不来——完美挡住了毛刺。

三、寄存器 (Register) — DFF 的阵列化

寄存器 / 寄存器文件 (Register File) · N 个 DFF 并联

1 bit 寄存器 = 1 个 DFF（~24T）。32-bit 寄存器 = 32 个 DFF 并列，共享同一时钟。

CPU 中的寄存器文件（Register File）：比如 ARM 的 31 个通用寄存器（x0–x30），每个 64-bit = 31×64 = 1,984 个 DFF ≈ ~47,000 个晶体管，仅寄存器文件本身就相当可观。

寄存器文件还包括：

  • 写译码器——指令中的目标寄存器号 → 选中哪一组 DFF 的使能端
  • 读多路选择器——从所有寄存器中选出两个源寄存器（双读口），各输出到 ALU 的 A/B 端口
  • 写数据线——计算结果写回目标寄存器

为什么 CPU 寄存器这么少？每个 bit 要 24 个晶体管 + 多端口译码/MUX 开销。扩展到几万个寄存器在面积和时序上都不现实。ARM 31 个通用寄存器 + 重命名寄存器（~200 个物理寄存器）是经过精密权衡的数字。

四、缓存 (Cache) — 和寄存器走不同的路

Cache 内部结构 · SRAM 6T 阵列 · 不是 DFF!

为什么 Cache 不用 DFF？每 bit 24T vs 6T，4 倍的差距。1MB 的 L2 Cache 如果用 DFF 实现 = 8M bits × 24T = 近 2 亿个晶体管，面积大得无法接受。用 SRAM 6T 单元，同样容量只用 ~5000 万晶体管。

Cache 的内部组成（以 32KB L1 数据缓存为例）：

  • 数据阵列（Data Array）：SRAM 6T 单元阵列，存实际数据。32KB = 512 行 × 64B（每行 512 bit）
  • 标签阵列（Tag Array）：也是 SRAM——存每行的地址标签 + 有效位(V) + 脏位(D)
  • 标签比较器：地址的 Tag 部分和 Tag Array 读出的值比较——是否命中？用 XOR + AND 树实现
  • 译码器：地址的 Index 部分选中 512 行中的一行
  • MUX / Way Selector：组相联缓存中，从 N 路中选出命中那一路的数据

🧠 记住这一个不等式

2 个锁存器 → 1 个触发器 → N 个触发器 → 1 个寄存器

Cache ≠ 一堆寄存器。Cache = SRAM 阵列，寄存器 = DFF 阵列。
