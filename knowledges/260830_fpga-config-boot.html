FPGA 配置机制 — bit 烧到哪、易失性、上电加载

260830 · FPGA配置SRAMQSPI易失性启动模式

🔑 一句话核心

FPGA 没有内置非易失存储。 bit 默认烧进它内部的 SRAM 配置存储——易失、断电即丢、上电变空白裸片。要"上电自动跑"，得把配置存到外部非易失的 QSPI Flash，让 FPGA 启动时自己加载。

三连答

问题答案
烧到哪？FPGA 内部 SRAM 配置存储（Configuration SRAM）
易失吗？易失——SRAM 结构，断电清零
重新上电还在吗？不在。每次上电 FPGA 都是空白，必须重新配置

机制：配置 SRAM 决定一切

FPGA 的"程序"（bitstream）不是代码，而是写进一大片 SRAM 配置单元，这些单元直接决定：

  • 每个 LUT 的真值表（SRAM 存的内容）
  • 每条 路由开关（互连网络）的导通
  • 每个 IOB 的方向/标准

上电后 FPGA 按启动流程把配置从来源灌进这片 SRAM，完成后 DONE 引脚拉高，进入用户模式开始跑。

上电（配置 SRAM 清零） → 按 M[2:0] 模式引脚选来源 → 从来源灌入 bitstream → DONE=1 → 用户模式运行

两种配置模式对比

模式配置来源易失性用途
JTAG 模式Vivado 经 JTAG 口直接灌进 SRAM易失调试阶段（反复试，随便折腾）
QSPI 启动FPGA 上电自己从板载 QSPI Flash 读非易失最终固化（上电自动运行）
🎯 A7-LITE 实例（阶段 0 亲历）
  1. 点灯 / UART 用的都是 JTAG → SRAM（调试模式）——断电就没了，下次上电得重新 Program。
  2. 板载 QSPI Flash = IS25L128F（128Mbit=16MB，NOR Flash，非易失）——阶段 5 的主角。
  3. 要"上电自动运行"：Vivado → Add Configuration Memory Device → 选 IS25L128F，把 bit 转 .bin/.mcs 烧进去，boot 模式切 QSPI。

与存储理论的衔接（易失 vs 非易失）

存储类型特性
FPGA 配置存储SRAM易失，供电即保持、断电丢失（无需刷新）
QSPI FlashNOR Flash非易失，断电保持（可反复擦写）

类比：SRAM 像"运行内存"，QSPI 像"硬盘"——程序放硬盘，跑时加载进内存。这也是为什么 JTAG 调试可以随便烧、不怕固化——每次都是临时 SRAM；而到 QSPI 阶段要小心"固化"动作（写错可能盖掉出厂固件，但 QSPI 可擦写，不算致命）。
