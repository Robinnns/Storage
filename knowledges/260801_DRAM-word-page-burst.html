DRAM 的 Word / Page / Burst — 和 C 语言 "Word" 的对比

260801 · DRAMWordlineRow BufferBurstCache Line

问题

DRAM 激活一根 WL 时，上面所有 BL 都读出来了——是不是有多少条 BL，一个字就等于多少 bit？这和 C 语言的 Word 是什么关系？

回答：五层抽象，每层的"一次读出"含义完全不同

🏗️ DRAM WL 激活
物理层
一根 WL 拉高 → 整行所有 BL 上存储单元同时连通到 Sense Amp → 整行数据进入 Row Buffer
1024–8192 bit
↓ Column Decoder 从中切一截
📌 Column Access
芯片接口层
Column Address 控制 Column Mux，从 Row Buffer（比如 1024 列）中选出窄的一截送到 DQ 引脚
4 / 8 / 16 bit
(x4 / x8 / x16)
↓ Burst: 连续送 N 个 Column
🔥 DDR Burst (一次 READ)
JEDEC 协议层
一个 READ 命令 → 连续 8 个 (DDR4) 或 16 个 (DDR5) 时钟沿的数据，DQ 宽度 × Burst Length
x8×8=64 bit
x16×8=128 bit
↓ 内存控制器可能合并多次 Burst + 多 Rank 并行
💾 Cache Line
CPU-内存接口
CPU 和 DRAM 之间的最小传输单位。一次 Cache Miss → 从 DRAM 搬一整条 Cache Line 填入 L1/L2
512 bit (64B)
↓ 软件看到的是这个
🖥️ C 语言 "Word"
软件层
sizeof(int) 取决于 ISA 和 ABI：ILP32 → 32 bit；LP64 → int=32bit, long=64bit, ptr=64bit。这是软件定义，和物理 BL 数量无关。

Row Buffer 示意图

🔑 核心结论

  1. WL 激活出来的那 1024–8192 bit 叫 Page / Row Buffer，不叫 Word。
  2. 同行的后续 Column 访问几乎零延迟（数据已在 Row Buffer），这就是 行局部性（Row Locality）——也是 C 语言中 array[i][j] 把 j 放内层遍历快得多的物理根源。
  3. C 语言的 int（32/64 bit）经过了 Row Buffer → Column Decoder → Burst Engine → 内存控制器 → Cache Line → Load/Store 指令 一共六层抽象，和物理 BL 数量没有直接对应关系。
  4. DRAM 习惯用 I/O 宽度（x4/x8/x16）描述 DQ 引脚数，这是芯片封装层面的概念；C 语言 Word 是 ISA/ABI 层面的概念——两者完全在不同抽象层。
